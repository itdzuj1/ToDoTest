# Демо-профили — изменения API

## Затронутые эндпоинты

- `GET /api/users` — добавлен список активных демо-профилей.
- `POST /api/users` — добавлено создание демо-профиля.
- `GET /api/users/{user}` — добавлено получение профиля по ID.

## Изменения в ответе

- Все endpoint-ы используют существующий `UserResource`.
- Коллекция не содержит заблокированные профили.
- Прямой запрос возвращает заблокированный профиль с `is_blocked: true`.
- Поле `todo_lists` отсутствует, поскольку связь не загружается этими endpoint-ами.

## Изменения в запросе

- `POST /api/users` принимает обязательное строковое поле `name` длиной до 80 символов.
- Имя нормализуется через trim/squish.
- Имя уникально без учёта регистра и повторяющихся пробелов.
- Дубликат возвращает HTTP 422 с ошибкой поля `name`.
- Поля вне контракта игнорируются.

## Breaking changes

- Нет: добавлены новые публичные endpoint-ы.

## Migration notes для фронта

- Для выбора профиля использовать `GET /api/users`.
- После создания сохранять `data.id` из ответа `POST /api/users`.
- При восстановлении локально сохранённого ID использовать `GET /api/users/{user}` и проверять
  `data.is_blocked`.
