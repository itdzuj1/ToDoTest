# Состояния и доменные правила

## Матрица состояний (обязательна для каждого экрана и запроса)
initial · loading · success · empty · error · disabled · submitting · deleting · read-only · archived · blocked

| Состояние | Как выглядит |
|---|---|
| loading | skeleton-полосы radius 9999 `#eef0f3`, высота строк не меняется; кнопки — спиннер 13px внутри, ширина фиксируется |
| empty | UiEmpty внутри таблицы на всю ширину: заголовок 20/650, подпись 14, одно действие |
| error | UiError: заголовок, код ответа, кнопка «Повторить». Данные не подменяются заглушками |
| submitting | primary-кнопка со спиннером, поля `disabled`, форма не даёт повторный submit |
| deleting | строка opacity .6, badge «Удаление…» danger, спиннер вместо меню |
| read-only / archived | контролы не исчезают, а получают `disabled` + иконку замка; сверху одна поясняющая полоса |
| blocked | warning-баннер + `aria-disabled` на всех мутациях; чтение доступно |

## Доменные правила
1. Заблокированный профиль доступен **для чтения**; любые мутации отключены на уровне layout.
2. Архивный список доступен для чтения; задачи архивного списка нельзя изменять.
3. Администратор управляет задачами **независимо** от blocked и archived.
4. Удаление задачи — только через явное подтверждение (чекбокс в public, ввод ID в admin).
5. Ошибки валидации привязаны к конкретному полю (`aria-invalid` + `aria-describedby`), не общим тостом.
6. «Тихие» ошибки запрещены: любое неуспешное действие видимо пользователю и содержит действие восстановления.

## Реализация
Состояния — модификаторы классов, не inline-стили: `.pt-table--loading`, `.ui-input--invalid`, `.pt-list-card--readonly`.
Плотность public/admin — переменные `--row-h` и `--control-h` на уровне layout.
